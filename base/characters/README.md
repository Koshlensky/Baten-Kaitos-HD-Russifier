# Справочник персонажей

- `_template.yaml` — шаблон карточки со всеми полями (раздел 4.1 задания).
- `shared/` — персонажи обеих игр (дух-хранитель, Georg, Larikush, Giacomo), `bk1/`, `bk2/` — по играм.
- `_evidence/<игра>.json` — улики по собственным репликам персонажа (по табличкам имени): число реплик, первая сцена, японская первая персона и вежливость, род в речи о себе в FR/ES/IT/DE (только BK1), обращения к собеседникам (французские tu/vous, японские местоимения второго лица), упоминания с he/she. Пересоздаётся `python -m tools.bkloc.char_evidence --game bk1|bk2`.
- `candidates_bk1.csv`, `candidates_bk2.csv` — автоматический список кандидатов. Пересоздаётся `python -m tools.bkloc.candidates`.

## Правила

1. Карточка нужна каждому персонажу, который говорит в сюжете или к которому обращаются; NPC второго плана — по мере перевода их сцен (сведения о них сначала попадают в память сцены, `base/memory/scenes/`).
2. Каждый факт — с источником и полем `confidence`:
   - `confirmed` — прямо сказано в тексте (описания, сводки, реплики) или следует из данных игры (табличка имени, код);
   - `inferred` — вывод из контекста, других локализаций, японских маркеров;
   - `unknown` — не установлено.
   Поле `basis` говорит, на чём держится факт: `text`, `data`, `other_loc`, `jp_marker`, `context`.
3. Японские языковые маркеры (первая персона, окончания, вежливость) сами по себе пол не доказывают. Такой факт получает `basis: jp_marker` и описывает манеру речи, а не пол.
4. Пол не выводится из одной английской фразы. Нужен явный источник: местоимения в описаниях и сводках, самоназвания, табличка, согласование в других локализациях.
5. Неподтверждённое — `unknown` и вопрос в `open_questions`.
6. Русское имя и род утверждаются только через [docs/DECISIONS.md](../../docs/DECISIONS.md); до этого `ru_name.status: pending`, `grammatical_gender_status: proposed`. В карточках русские имена не используются до утверждения.
7. `id` карточки используется в матрице (`speaker.id`, `addressee.id`). Поле `name_tags` (с префиксом игры: `bk1:PCN_1`) связывает таблички имени из скриптов с карточкой — матрица подставляет `id` карточки вместо ID таблички.
8. Отношения: `register_to` — как персонаж обращается к собеседнику (`ty`, `vy`, `mixed`, `unknown`), `register_status: proposed` до утверждения на пилоте, `changes` — точки смены обращения (D-006).
9. Статусы карточки: `draft` — собрано; `reviewed` — проверено по сценам; `approved` — утверждено.
