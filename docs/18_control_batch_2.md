Дата: 19.10.2026. Переводчик и редактор — Claude Sonnet 5.5 Medium в отдельных сессиях; Opus не запускался; On-Demand выключен.

## Оптимизация контекста

Вместо отдельной сессии на каждый пакет — «рабочие единицы» из 100–150 строк подряд (`tools/bkloc/units.py`, `mass units/upackets/uapply`):
- справочники (правила, карточки, глоссарий, память) передаются один раз на единицу;
- карточки: только нужные поля и связи между присутствующими персонажами; глоссарий: `en`, `ru`, статус, рекомендация (без форм и источников);
- строки: неизвестные поля опускаются, JSON без отступов; контекст «готовые строки» ограничен;
- сюжетная память: BK1 — хвост общей памяти, BK2 — только разделы событий до места пакета в очереди; для мест без привязки и служебных наборов памяти нет (D-030).

Объём входа на строку (символы): первая контрольная партия — переводчик ≈ 1030, редактор ≈ 1090 (всего ≈ 2110); эта партия — переводчик ≈ 270, редактор ≈ 370 (всего ≈ 640). Входной объём меньше в **3,3 раза** (переводчик 3,7×, редактор 2,9×). Число сессий на строку тоже снизилось (16 сессий на 970 строк против 24 на 465).

Независимость сохранена: переводчик и редактор — разные сессии с разными входами; редактор не получает заметки переводчика; редактор получает собственную инструкцию (`prompts/editor.md`) и сводку памяти (`__memory__`) для следующих единиц.

## Что снизилось и почему важно проверить

Доля правок упала с 19,8% до 12,1%. Возможные причины: часть партии — второстепенные реплики (меньше ошибок), более точный промпт переводчика, строже глоссарий. Но возможна и меньшая строгость редактора при сжатом входе. Проверить это без Opus нельзя; рекомендуется выборочный контроль Opus на 40–60 строк из этой партии (по согласованию), если качество важнее экономии.
