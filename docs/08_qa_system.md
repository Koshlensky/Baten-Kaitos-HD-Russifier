# Система контроля качества

Автоматические проверки ловят технические и типовые языковые ошибки. Они **не заменяют** литературную редактуру: финальная редактура каждой строки делается по английскому оригиналу (этап 12), без опоры на какой-либо другой перевод.

## Запуск

```powershell
.\.venv\Scripts\python.exe -m tools.qa.run_qa                     # обе игры
.\.venv\Scripts\python.exe -m tools.qa.run_qa --batch bk1:B0209    # один пакет
.\.venv\Scripts\python.exe -m tools.qa.run_qa --build              # плюс сборка в копию бандла
.\.venv\Scripts\python.exe -m tools.qa.run_qa --selftest           # самотест проверок
.\.venv\Scripts\python.exe -m tools.qa.validate_matrix             # только структура матрицы
.\.venv\Scripts\python.exe -m tools.qa.legacy_guard                # только карантин v1.0
```

Отчёты: `reports/qa/qa_<время>.md` (сводка) и `.json` (все находки с примерами). Код возврата 1 — есть блокирующие ошибки.

## Уровни

- **error** — блокирует переход строки в `auto_checked` и сборку. Снять нельзя, только исправить.
- **warning** — смотрит редактор. Если после проверки всё верно, предупреждение снимается флагом `waive:<код>` в `qa_flags` строки (с комментарием в `editor_note`).
- **info** — справочно.

## Когда запускать

- После каждого `pipeline apply` переводчика — `run_qa --batch <пакет>`; ошибки исправляются до редактуры.
- После редактуры пакета — снова `run_qa --batch`.
- Ежедневно и перед каждым коммитом главы — `run_qa`.
- Перед сборкой установщика — `run_qa --build` без ошибок и без неснятых предупреждений категорий `gender_*`, `tags_*`, `placeholders`, `glossary_*`.

## Что дорабатывается на пилоте (этап 9)

- Калибровка ширины: скриншоты окон диалога, меню, карточек магнусов → пороги для групп строк вместо сравнения с оригиналом.
- Число строк на страницу облачка с учётом автопереноса.
- Сводки по персонажам: доля мужских и женских форм в репликах каждого персонажа, обращения «ты/вы» по парам.
- Согласованность названий магнусов в описаниях и репликах.
- Проверка ложных срабатываний `gender_lint` на реальном тексте и уточнение правил. Выполнено на пилоте: теги паузы и облачка — граница предложения для `gender_lint`; подстановка имени заменяется словом в построчных проверках; двойной пробел — только если его нет в оригинале; «вы» к группе не нарушает пару на «ты»; словарные слова не считаются искажёнными именами. Каждое исправление закреплено в самотесте (`run_qa --selftest`) — [11_pilot_results.md](11_pilot_results.md), раздел 2.
- Подсказки редактору (уровень info) по итогам пилота: строки-близнецы с разным переводом, усилители без опоры в оригинале, модальные глаголы оригинала, повторяющиеся формулы.

## Ручная проверка в игре (этапы 9 и 14)

Чек-лист: стартовые экраны и меню обеих игр; первые сцены; длинная катсцена с озвучкой (`<v>`, автопереходы `<wN>`); меню выбора; лавка; бой и экран результатов; карточки магнусов и описания; справка; сохранение и загрузка; сцена с `<n0>`; варианты реплик духа (`_0/_1`) в BK1; письма и дневник BK2. Для каждой проблемы — скриншот, ID строки, запись в отчёте.
